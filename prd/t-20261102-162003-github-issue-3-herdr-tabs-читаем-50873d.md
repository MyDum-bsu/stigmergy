# PRD — Herdr tabs: читаемые имена и автоматическая уборка

Задача: `t-20261102-162003-github-issue-3-herdr-tabs-читаем-50873d`
Источник: GitHub issue MyDum-bsu/stigmergy#3 (зеркало; источник истины — доска).

## Goal

Вкладки Herdr перестают быть свалкой из длинных `t-...` id: каждая Plan/Worker/Critic
вкладка получает читаемый label из title задачи плюс короткий стабильный маркер,
закрывается по завершении задачи (не только после merge), а уборка осиротевших и
завершённых вкладок не трогает Lead и Board и не создаёт второй Lead/space.

Что становится правдой после мержа:

- имя вкладки читаемо человеку и однозначно привязано к задаче (`Plan · <title> [abc123]`);
- `stg episode finish`, `stg worker done`, `stg plan approve` закрывают Plan/worker/Critic
  вкладки этой задачи сразу, независимо от merge;
- `stg app cleanup` закрывает вкладки задач в терминальном статусе и осиротевшие,
  но никогда Lead/Board;
- повторный `stg lead` не создаёт второй space и вторую Lead-вкладку.

## Non-goals

- Никакой замены доски: Herdr остаётся runtime, статусы вкладок — не вердикт.
- Не переписывается `herdr` (CLI-сессия, workspaces `stg-*`) — там поведение уже есть и
  не является предметом issue; трогаем только `herdr-app` (space/tabs) и, при
  необходимости, parity-вызовы.
- Не меняется схема событий доски, gate, merge, spec-контур.
- Не вводится второй трекер (issue/вкладка не заменяют `board.done`).
- Не настраивается внешний вид Herdr (темы, шрифты, раскладка) и не добавляется новых
  зависимостей.
- Автоматическая периодическая уборка как отдельный таймер не вводится, если её нет
  сейчас: уборка вызывается из уже существующих точек (`cleanup`-CLI, dispatcher tick).

## Use cases

1. Планировщик открывает Plan-вкладку по задаче с длинным id — в заголовке видно
   `Plan · Herdr tabs: читаемые имена [50873d]`, а не `t-20261102-162003-...`.
2. Диспетчер/wave открывает worker-вкладку — тот же формат с маркером задачи.
3. Воркер сдал работу (`stg worker done`), мерж ещё не прошёл — Plan/worker/Critic
   вкладки этой задачи уже закрыты, space не висит с мёртвыми агентами.
4. Человек одобрил план (`stg plan approve`) — Plan-вкладка этой задачи закрыта.
5. Человек запускает `stg app cleanup` утром — уходят вкладки завершённых и
   осиротевших задач, Lead и Board остаются, живые задачи не трогаются.
6. Человек повторно запускает `stg lead` — открывается/фокусируется существующая
   Lead-вкладка в space проекта, второго space `stigmergy` не появляется.

## UX

- Формат label: `"<Kind> · <title> [<short>]"`, где Kind ∈ {Plan, Worker, Critic},
  title — очищенный и обрезанный title задачи, short — 6 строчных hex-символов.
- `MAX_TAB_LABEL = 48` символов; обрезка по символам (не байтам) с `…`, маркер
  `[short]` всегда сохраняется целиком.
- Из title вырезаются: сам `task_id`, токены вида `t-YYYYMMDD-HHMMSS-...`; пустой
  после очистки title даёт `"<Kind> · [<short>]"`.
- `stg app cleanup` печатает закрытые имена по одному в строке, `nothing to close`
  при пустом результате; `--dry-run` печатает то же, но ничего не закрывает.
- Ошибка Herdr-app не маскируется: CLI завершается ненулевым кодом и печатает причину.
  В точках завершения задачи (finish/approve/worker done) ошибка Herdr не валит
  основную операцию: печатается одна строка `herdr: tabs not closed: <reason>`,
  exit-код остаётся кодом основной операции.
- Один space проекта, одна Lead-вкладка с именем ровно `Lead`; Lead и Board
  закреплены и не закрываются уборкой никогда.

## Edge cases

- title содержит `·` — маркер всё равно в конце, парсинг идёт с конца.
- title длиной 300+ символов и кириллица — обрезка по символам, маркер цел.
- title пустой или состоит из одного slug задачи — label остаётся валидным.
- две задачи с одинаковым title — различаются маркером.
- вкладка со старым именем (`Plan · <task_id>`, `<task_id> · worker`, `stg-<task_id>`)
  закрывается так же, как новая (обратная совместимость имён).
- вкладка без терминалов или с мёртвым терминалом и неизвестным маркером — осиротевшая.
- вкладка с `created_at` моложе `stale_after_s` и живым терминалом — не закрывается.
- Lead-вкладка, в имени которой случайно оказался маркер завершённой задачи, всё равно
  не закрывается (защита приоритетнее статуса).
- пустой список space/tabs — пустой результат, без исключения.
- herdr-app не запущен / `hc` недоступен — `HerdrAppError` пробрасывается, не глотается.
- две Lead-вкладки, оставшиеся от прошлых запусков — вторая закрывается как дубль,
  space остаётся один.

## Risks

- **Уборка закрывает не то.** Вкладка — живой терминал агента; ошибочное закрытие
  убивает работу. Смягчение: защита Lead/Board проверяется до любых правил, закрытие
  только по явному предикату, `--dry-run`, отдельный oracle-тест на приоритет защиты,
  negative control с мутантом «защита всегда False».
- **Маркер-хеш не совпал с задачей.** 6 hex-символов дают коллизию при ~4k живых
  задачах. Смягчение: маркер проверяется вместе с Kind-префиксом, коллизия влияет
  только на уборку и видна в `--dry-run`; при необходимости длина увеличивается одним
  аргументом `short_id(task_id, length)`.
- **Автозакрытие после approve/finish мешает человеку дочитать вывод агента.**
  Смягчение: закрываются только Plan/worker/Critic этой задачи, не space; Lead
  остаётся; вывод остаётся в `.agent`-логах и `stg board show`.
- **Расширение allowed_paths до вызовов из episode/intake/dispatcher** может задеть
  чужой код. Смягчение: правки только в точках вызова одной функцией
  `close_task_tabs`, без рефакторинга вокруг.
- **Negative kit привязан к телу `is_protected_tab`.** Если воркер напишет защиту
  иначе, patch не применится и gate это увидит; поэтому сигнатура, докстринг и
  выражение зафиксированы в спеке дословно.

## Verification plan

1. `dod` (одна команда): oracle-тесты в `oracle/<ID>/test_herdr_tabs_oracle.py`
   падают до правки (нет `short_id`/`tab_label`/`cleanup_tabs`/`ensure_lead_tab`)
   и проходят после.
2. Собственные тесты воркера рядом с кодом: `uv run pytest -q tests/test_herdr_app.py tests/test_herdr.py`
   (существующий `tests/test_herdr.py` не должен сломаться — parity cleanup в `herdr`).
3. `uv run ruff check .` — общие контракты модуля затронуты, линт по репозиторию.
4. Negative control: кит `oracle/negative/<ID>/kit.patch` (защита Lead/Board всегда
   `False`) — oracle-тесты обязаны упасть на этом дереве.
5. Ручная проверка UX на живом Herdr (не в gate): `stg app cleanup --dry-run` на
   текущем space, глазами сверить, что в списке нет Lead/Board и живых задач.
